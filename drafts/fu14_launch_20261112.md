## 0. Quotas read on 2026-11-12 (read-only, by the agent)

- `GPUS-ALL-REGIONS-per-project`: 10.
- `NVIDIA-A100-80GB-GPUS-per-project-region` (on demand) and `PREEMPTIBLE-NVIDIA-A100-80GB-GPUS-per-project-region`
  (Spot): us-central1 2, us-east4 1, us-east5 1, europe-west4 1.
- `PREEMPTIBLE-NVIDIA-H100-GPUS-per-project-region`: 64, the default value for every region. This is where the H100
  Spot quota of follow-up 9 comes from: newer GPU quotas exist only in Cloud Quotas, so `gcloud compute regions
  describe` lists no H100 line (follow-up 9's row of 2026-10-29: "Quotas (Cloud Quotas): Spot H100 64 per region").
  There is no on-demand `NVIDIA-H100-GPUS` value.
- v5e: `v5litepod-1` is offered in europe-west4-a and europe-west4-b; europe-west4-c offers no TPU type at all, so the
  only reserve zone is europe-west4-a.
- No `af3-run` instance and no TPU VM in europe-west4-b.

Commands to read them again just before the launch:

```
gcloud beta quotas info describe GPUS-ALL-REGIONS-per-project --service=compute.googleapis.com --project=af2-tpu-benchmark --format="value(dimensionsInfos[0].details.value)"
```

```
for q in PREEMPTIBLE-NVIDIA-H100-GPUS-per-project-region PREEMPTIBLE-NVIDIA-A100-80GB-GPUS-per-project-region NVIDIA-A100-80GB-GPUS-per-project-region; do echo "== $q"; gcloud beta quotas info describe $q --service=compute.googleapis.com --project=af2-tpu-benchmark --flatten="dimensionsInfos[]" --format="table(dimensionsInfos.dimensions.region,dimensionsInfos.details.value)"; done
```

```
gcloud beta quotas info describe TPUV5sLitepodPerProjectPerZoneForTPUAPI --service=tpu.googleapis.com --project=af2-tpu-benchmark --flatten="dimensionsInfos[]" --format="table(dimensionsInfos.dimensions.zone,dimensionsInfos.details.value)"
```

```
for z in europe-west4-a europe-west4-b europe-west4-c; do echo "== $z"; gcloud compute tpus tpu-vm accelerator-types list --zone=$z --project=af2-tpu-benchmark --format="value(name)" | grep "v5litepod-1$"; done
```

```
gcloud compute instances list --project=af2-tpu-benchmark --filter="name~^af3-run" --format="table(name,zone.basename(),status)"
```

### During the runs

- **Stop rule.** If `results/f32_cap_stop.txt` appears, the A100 wrapper starts no further part (running parts finish).
  Stop that wrapper with Ctrl-C (its retry rounds would only be refused again), and decide in a section 10 row whether
  to raise the cap or to leave Af incomplete. Every guard decision is in `results/f32_guard.tsv`.
- **A100 fallback on demand.** If an Af part has not obtained a Spot VM within 2 h of the wrapper's start: write the
  row, stop the A100 Spot wrapper with Ctrl-C between attempts (running parts go on), then, with `MAX_A100` equal to 5
  minus the A100 Spot VMs still running:

  ```
  caffeinate -dims bash ~/Desktop/af3_drafts/retry_arm_par.sh results/parts_f32_a100_ondemand.txt SPOT=0 MAX_A100=5 A100_MACHINE_TYPE=a2-ultragpu-1g LAUNCHER=scripts/monitor/fu14_guarded_launch.sh ALLOW_OTHER_LAUNCHERS=1
  ```

  The wrapper skips every part that already had a VM, so only the parts without one run on demand; the guard prices
  them on demand.
- **v5e reserve zone.** If the v5e parts find no capacity in europe-west4-b for a long time: write the row, stop the
  v5e wrapper with Ctrl-C between attempts, then:

  ```
  caffeinate -dims bash ~/Desktop/af3_drafts/retry_arm_par.sh results/parts_f32_v5e_ew4a.txt MAX_V5E=4 ALLOW_OTHER_LAUNCHERS=1
  ```
